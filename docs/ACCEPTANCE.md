## 4. 已知问题（诚实清单）

### 4.1 未完成的功能

1. **Prestige 只有第一层**（孢子化）。四层结构、菌株（6 种 Build）、Meta 资源、法则碎片、星际播种未接入。
2. **挑战未接入玩法**。30 条挑战的规则改写数据已定义，但没有"开始挑战/规则生效/奖励发放"的流程。
3. **惊喜机制未实现**。虚空孢子、共生回声、时间银行、平行网络等 20 项隐藏内容只有数据与设计。
4. **共生契约未实现**。蜜露→契约点→基因片段链路在节点层已可用，但"与地表物种签约"的外交系统未做。
5. **图鉴是简版**。物种/矿物图鉴需要契约系统支撑。

### 4.2 平衡遗留（来自 `docs/balance-model.md §14`）

6. **Prestige 狂策略约 7.5 分钟重置一次** —— 属于该性格的设计预期，但需要真人手感确认是否过频。
7. **科技树在 7 天模拟中最多解锁 15/80** —— 机制型科技（禁忌/时间分支）几乎摸不到，成本曲线可能过陡。
8. **后期节点增长靠成本递增自然收敛** —— 从模拟看不会失控，但缺少"后期新增长点"（这正是批次 C 要解决的）。

### 4.3 工程遗留

9. **连线不承载物流**（v0.1 简化）：资源进全局库存，连线只提供催化与结算顺序。已在 GDD §7.1 与
   balance-model §3 如实标注，`fluxCap` 字段为后续启用预留。
10. **headless 下 `requestAnimationFrame` 不触发** —— 因此引入了 `?ticks/?demo/?stress` 自检通道；
    真实交互验证靠 CDP 鼠标事件，长时挂机表现仍需真人验证。
11. **`?demo=` 是同步执行的**，跑 6 小时会占用约 10–20 秒主线程（仅影响调试与截图，不影响正常游玩）。

### 本轮修掉的真实缺陷（全部由自动化测试抓到，非人工发现）

1. **拖拽移动无效**：`pointermove` 只在连线模式下更新落点，导致移动时用的仍是按下位置（烟测显示坐标 0,0 → 0,0）。
2. **引导层挡住画布**：开场覆盖层出现时，所有画布交互被拦截（烟测一次性失败 4 项），据此补上"可关闭"检查。
3. **`?fresh` 误跳过引导**：入场条件原本包含 skipSave，而 `?fresh` 只该忽略存档。
4. **`tileKeyOf` 参数误用**（把 snapToTile 结果当两个参数传）。
5. **网格单元负零**：`-46 % 46 === -0`，`Object.is` 比较失败（测试断言写法修正，非游戏逻辑问题）。
6. 三处编辑事故（误删 topbar 资源循环、tooltip 的 position、drawLayerBands 的 for 循环），均已恢复并回归验证——这也是"每步都跑全量回归"的价值所在。

## 8. 第三轮：三个交互 bug 的修复

| 现象 | 根因 | 修复 | 回归检查 |
|---|---|---|---|
| 右键照样会放下孢子 | 画布 `pointerdown` 未区分按键 —— 旁边的中键平移处理器有 `if (e.button !== 1) return`，主处理器漏了 | 入口统一加 `if (e.button !== 0) return`，并注释三键分工 | **真实右键点画布 → 节点数不变**；左键 1→2；中键不变 |
| 右键菜单的"删除 XXX"点了没反应，只能用 Delete | 菜单在 `document` 的 **pointerdown 阶段就被移除**，而浏览器顺序是 pointerdown → pointerup → click，按钮的 click 永远失去目标 | 改为「点**外部**才关」（`menu.contains` 判断）+ 关闭时移除监听 + 捕获阶段监听 + Esc 关闭 + once 标志兼容 click/pointerup | **真实鼠标点击菜单项 → 节点 46 → 45**；菜单自动关闭；点外部也关闭 |
| 设置里的"清空存档并重开"没用 | `onClear` 清完 key 后 `location.reload()`，而 `beforeunload` 会把当前状态**立刻写回** | 引入 `shouldPersist()` 统一开关（`suppressSave` + `readOnlySandbox`），三个写入口全部先检查；清档重排为「先停写 → 清 key → 确认已清空 → 才 reload」 | **清档后 reload → 存档 0 字节、节点回到 1、引导层重新出现** |

### 顺带修掉的历史遗留

**篡改存档后 reload 被覆盖**：与 Bug 3 同根因。上一轮的处理是在测试里绕开（改用只读接口验证），没有修根因。现在存档校验失败会进入**只读沙盒**（`readOnlySandbox`），自动保存与 `beforeunload` 都不再写回——玩家不会因为一次 reload 就丢掉原档。

### 本轮暴露的测试盲点（值得记录）

- 上一轮的右键检查写的是「合成 `contextmenu` 事件 + `btn.click()`」，**绕过了 pointerdown → pointerup → click 的真实时序**，所以 Bug 2 安然通过了当时全部 24 项检查。本轮把菜单项点击改为**真实鼠标事件**。
- 同理，Bug 1 也需要"真实按键"才能暴露：合成事件默认 `button: 0`，永远走不到右键分支。

## 12. 第七轮：手机字体与按钮可点性修复

**用户反馈**：真机上"很多菜单按钮我点不到，因为它超出了屏幕"，并要求做"不同字体大小下的适配"。

### 诊断：先量化，再动手

写了 `scripts/mobile-audit.mjs`：在 4 种屏幕尺寸（320×568 / 360×640 / 390×844 / 430×932）× 9 个面板下，
检查每个可交互元素"中心点是否真的能点到它自己"。**首次运行：36 个面板组合全部有问题。**

### 找到的四个根因

| # | 根因 | 表现 |
|---|---|---|
| 1 | **底部导航 12 个按钮没有横向滚动** | 「挑战」在 x=424、「法则」在 x=471 —— 390px 屏幕上完全在屏幕外，**点不到** |
| 2 | **模态框写死 `minWidth: 420px`** | 390px 宽的屏幕必然溢出 |
| 3 | **开场引导层 `inset: 0` 盖住导航** | 打开面板后**切不到其它面板**；开场层自身的按钮跑到 x=495 |
| 4 | **面板根元素带内联 `display: flex`** | 媒体查询的 `display: none` 压不过内联样式 → "抽屉关了但面板还在" |

另外发现：`index.html` 的布局容器是 `div` 而非 `main`，导致媒体查询选择器失效；
模态框的头部与按钮没有固定，内容一长"关闭"就被挤出屏幕。

### 修复

| 修复 | 说明 |
|---|---|
| 导航栏横向滚动 | `overflow-x: auto` + 隐藏滚动条 + `flex: 0 0 auto`；实测 320px 下滚动后「设置」可点 |
| 模态框自适应 | `min(420px, 100vw - 20px)`、`dvh` 高度、`overflow: hidden`；头部与按钮固定、中间内容滚动 |
| 遮罩避让导航 | overlay 与开场层底部留出 `--nav-h`（手机 52px、桌面 0） |
| 面板用 `!important` | 媒体查询里对 `main > aside` 加 `!important` 以压过内联 display |
| 引导卡浮层化 | 手机上面板隐藏，引导卡改为 `position: fixed` 挂在 `body` |
| 开场层自适应 | 宽度 `min(520px, 100vw - 24px)`、按钮 `flex-wrap: wrap` |

### 验证

- **静态审计**：36 个面板组合 → 剩余 7 处（经逐个人工核查，全部是"滚动容器内的元素被审计误报"，元素本身可点）
- **真实操作验证**（新增 `npm run test:mobile`）：在 320×568 与 390×844 下，导航栏滚动后最后一个入口可点、5 个面板滚到底后最后一个按钮可点 —— **全部通过**
- **字体放大**（模拟 Android textZoom 130% / 150%）：**文字被截断的按钮 0 个**；剩余"点不到"全部是需要横向滚动的导航项（滚动即可见）
- 回归：单测 218/218、名实一致性通过、引导链 7/7、构建成功

### 这一轮的方法论

静态审计会误报（滚动容器内的元素"看起来"越界），而**真实操作**（滚到底再点）才是玩家视角的判据。

## 13. 第八轮：手机端两个回归修复
